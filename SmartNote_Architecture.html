SmartNote — Architecture Overview

Flutter offline-first notes app with SQLite local persistence and optional Supabase synchronization.

1. Business Context

Users

Người dùng mobile

Ghi chú nhanh, checklist, ảnh, tag, tìm kiếm và nhắc nhở.

Objective

Offline-first

Đọc/ghi dữ liệu ngay cả khi không có Internet; cloud chỉ là lớp đồng bộ tùy chọn.

Value

Độ tin cậy

Thao tác người dùng được lưu local trước, giảm phụ thuộc vào độ ổn định mạng.

Outcome

Trải nghiệm liên tục

Ứng dụng phản hồi nhanh, hỗ trợ nhắc nhở, export và đa ngôn ngữ.

2. Data Flow

Màu theo skill: xanh dương = data, cam = processing, tím = service/application, xanh lá = successful output/cloud.

4. Layered System Architecture

Presentation / UI
Flutter screens, widgets, routing via go_router, localization and user interaction.
Application
Riverpod state + orchestration of note use cases, reminders, export and sync actions.
Domain
Note, ChecklistItem, query/validator and repository contracts.
Data
SQLite repositories, smartnote.db, drafts, versions, reminder state and sync outbox.
External Services
Optional Supabase cloud synchronization and external REST source for inspiration content.

5. Features

Notes

Text/checklist, edit, soft delete, favorites, colors.

Organization

Tags, search/filter, images.

Productivity

Reminders, drafts, version history.

Security

Lock state and security feature module.

Export

PDF generation and system share.

Experience

Light/dark theme and Vietnamese/English localization.

6. Deployment & Runtime

Client

Flutter mobile application. Local runtime requires SQLite database and app assets.

Cloud (optional)

Supabase project/configuration for synchronization. Offline usage does not require cloud availability.

Workflow

Build Flutter app → initialize local DB → user operates offline → sync service pushes outbox when configured.

Architecture derived from SmartNote code structure, pubspec dependencies, Note domain model, SQLite schema and sync module.
